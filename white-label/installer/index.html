STEP 02 — INFRASTRUCTURE

Owned by the company.

Each company uses a completely separate Supabase project and hosting site. The production connector will request permission to create and configure these resources.

Secure staging connections

Connect your own Supabase account first, then authorise your Netlify account. Both grants are encrypted in the separate Klean.ly Business control plane and can be checked or disconnected. A connection never creates a customer site or database; installations remain disabled.

STEP 03 — YOUR SERVICES

Connect what you use.

Maps, email, card payments, direct debits and SMS will all use the company's own accounts and billing. Choose which integrations this installation will need.

Providers are not connected by selecting them.

Preferences are saved in the installation blueprint. Actual authorisation, API-key verification and secure server-side configuration come next.

Check free project capacity

Ask Supabase to confirm the connected organisation's current plan and count all projects visible to the account. This is a read-only check; project creation remains locked.

Prepare one test Supabase project

Review the organisation, region, project name and cost safeguards. Creation stays locked until explicitly enabled and separately approved. Reviewing will not create anything.

Create one real test project

A real Supabase project will be created in your connected test organisation. This may use your Free Plan quota. Supabase determines final availability, region and any applicable costs. We will request no paid add-ons. No website or CRM tables will be created at this step.

Check your test CRM database

Confirm the new Supabase project's identity, final region and whether the dedicated CRM tables already exist. This is a read-only check; no schema is installed.

Review CRM schema installation

Preview the cleaning business tables, owner security and remaining setup. This review cannot install any tables and requires the verified test database.

Prepare one CRM schema installation

Recheck the dedicated test database and the single-attempt safety lock before installation. Reviewing is read-only: no tables or accounts will be created.

Install ONE real CRM schema

This creates the 8 business tables, private version tracking and row-level security in the approved Frankfurt test project. This change cannot be automatically undone. No customer data, owner login, Netlify site or CRM application is created.

Check business owner login readiness

Verify the eight protected CRM tables and whether a business owner is already assigned. Read-only: this will not create a login, send email or change your database.

Review CRM website

Check the separate Netlify account connected to this installer, its teams, and whether your proposed CRM test website name is already visible. Read-only: no website or login will be created.

Check Free Plan hosting limits

Verify your approved kleanlytest Netlify team is still on its Free Plan, check its existing website count and recheck the chosen CRM address. Read-only: no website or billing change.

Prepare one CRM website

Review the test Netlify team's Free Plan and the one-site safety lock before creating a website. This check is read-only and creates nothing.

Create ONE real CRM website

This creates one EMPTY Netlify website at kleanly-business-crm-pilot.netlify.app in the separately connected kleanlytest Free Plan team. No paid add-ons, custom domain, CRM app, owner login, or invitation will be created.

Check CRM deployment readiness

Safely check the new Netlify test website, its Free Plan team, and whether any files have already been deployed. This is read-only: no website, CRM application, login or deployment will be changed.

Review CRM deployment package

Check the real CRM source files, owner login callback, security headers, and package fingerprint. This is a code-only review: no API keys, accounts, email or website deployment is involved.

Verify test CRM publishable key

Use only the publishable key from the separate Klean.ly Business test Supabase project's Settings → API Keys. It starts with sb_publishable_. The key is checked against that test project and discarded immediately: nothing is saved or deployed. NEVER use a secret or service-role key.
